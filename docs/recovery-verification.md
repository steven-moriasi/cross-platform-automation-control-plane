# Recovery verification

Recovery claims in this repository are exercised against the disposable local
runtime. Each drill writes a timestamped JSON result and supporting hashes or
inventories under `.data/recovery/`. That directory is intentionally ignored:
evidence should be generated by the reviewer from the revision being assessed,
not presented as a permanently current result.

## PostgreSQL backup and restore

```bash
scripts/operations/postgres-restore-drill.sh
```

The drill:

1. creates a custom-format PostgreSQL backup;
2. restores it into an isolated temporary database;
3. compares exact counts for the control-plane authority tables;
4. compares every applied migration checksum;
5. records backup, count-inventory, and migration-inventory SHA-256 hashes;
6. drops the temporary database.

The backup file remains beside the report so its checksum can be independently
verified. It contains only the synthetic local dataset and must not be
committed.

## Migration integrity

```bash
scripts/operations/verify-migrations.sh
```

The migration runner uses a PostgreSQL advisory lock, one transaction per
migration, and a stored SHA-256 checksum. The verification script runs the
normal migration job and compares the database inventory with hashes computed
from the checked-out SQL files. An applied migration edited in place causes the
job to fail rather than silently changing history.

## Worker lease recovery

```bash
scripts/operations/outbox-recovery-drill.sh
```

The drill stops the worker, inserts a synthetic outbox message carrying an
expired lease from a terminated worker, starts the worker, and verifies that the
message becomes processed within 30 seconds. It records the final attempt count
and processing timestamp, then removes the drill message.

This exercise proves recovery after lease expiry. Retry exhaustion and
dead-letter insertion remain covered by the repository implementation and unit
tests; operators must investigate rather than automatically replay a dead letter
because its side effect may be uncertain.

## Automation-specific reconciliation

Platform-specific runbooks under `docs/runbooks/` define the resource query,
idempotency key, telemetry replay, and evidence steps for each reference
automation. An uncertain mutation is always queried before retry; the control
plane does not claim cross-platform exactly-once processing.
